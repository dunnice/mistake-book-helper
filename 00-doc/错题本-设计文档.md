## 一、系统目标

为初中生建立一套**错题从收集到真正掌握的闭环系统**：

- 错题不遗漏：每次考试/作业的错题都被 AI 批改、提取、归档
- 重做有闭环：打印重做卷 → 纸上重做 → 扫码对答案 → 系统记录结果
- 掌握可量化：连续 2 次做对自动标记"已掌握"，高频易错知识点自动统计
- 复盘自动化：AI 定期读统计，生成易错点报告和针对性重做卷

## 二、五段闭环（工作流分解）

| 段 | 名称 | 流程 | 执行方 |
|---|---|---|---|
| ① | 收集 | 拍卷子 → AI 批改、提取错题、知识点打标 → API 入库 | 手机 + AI + 云 |
| ② | 消化 | 网页筛选错题 → 打印组卷（每题带二维码，答案不上纸）→ 纸上重做 | 电脑 + 纸笔 |
| ③ | 反馈 | 扫二维码 → 先自己做 → 对答案 → 点"我做对了/做错了" | 手机 |
| ④ | 掌握 | 云端记录重做结果，连续 2 次对 = 已掌握；统计易错知识点排行 | 云 |
| ⑤ | 复盘 | AI 读 `/api/v1/stats` → 周报/易错点分析 → 按易错点智能出卷 → 回到② | AI |

闭环的关键：⑤ 的产出（重做卷）回到 ②，形成循环，直到知识点被掌握。

## 三、四方职责分工

### AI Agent —— 智能层，无状态
- 识别卷子照片，逐题判定对错
- 把错题提取为结构化 JSON（字段见 README 的入库格式）
- 知识点打标（按初中各科知识体系归一化，用词与知识点字典一致）
- 生成 answer / analysis / error_reason 判断
- 定期（周）读统计接口，生成易错点报告、推荐重做卷筛选条件
- **不存储任何学生数据**；与系统只有一条通道：`X-API-Key` 鉴权的 REST API

### 云端（阿里云 Go 单容器）—— 数据层，唯一数据源
- 存储：MySQL（生产）/ SQLite（本地演示），错题表 + 重做记录表
- API：错题 CRUD、重做记录、统计聚合、二维码 PNG 生成
- 掌握判定规则内聚在云端（连续 2 次对 = 已掌握），不依赖 AI 在场
- 托管三个页面：`/` 管理端、`/print` 打印组卷、`/m/:id` 扫码页

### 本地（电脑浏览器）—— 管理层
- 错题列表/详情/编辑、按科目/知识点/状态筛选
- 组卷打印（答案不上纸，二维码旁只有题号）
- 统计看板浏览
- 无本地数据，刷新即最新（数据全在云上）

### 手机端（扫码页）—— 反馈层
- 免鉴权打开单题（URL 不可枚举即可接受的安全模型，后续加 token）
- 隐藏"我的答案"，防止孩子看着原答案改
- 提交重做结果（对/错 + 可选答案/备注）
- 远期：拍照上传重做后的卷子，交 AI 复批，替代手动点对错

## 四、现状盘点

### 已具备（代码骨架完整）
- Go + Gin + GORM 服务端，双数据库支持，Docker 部署方案齐全
- 数据模型合理：Question（错题）+ Review（重做记录），MasteryStreak=2
- 三个前端页面 + 完整 API（含免鉴权移动端只读/提交）
- AI Agent 入库 JSON 契约已定义，使用手册已写

### 缺口（按优先级）
1. **知识点没有字典**：AI 打标用词不固定，统计会碎片化（"一元二次方程" vs "解一元二次方程"算两个）。→ 建 `knowledge_points` 字典表（id + 学科 + 标准名），AI 入库时传标准名或由云端做别名归一。
2. **免鉴权提交接口可被刷**：`POST /api/v1/m/:id/review` 无任何校验。→ 打印时二维码 URL 带一次性签名 token（HMAC，含题目 ID + 过期时间），提交时校验。
3. **原题截图字段空置**：`image_url` 未用。→ 本地/云端加上传接口，图片存服务器 `./data` 目录，打印卷可带缩略图，手机端可看原题。
4. **AI 入库靠手动口头指令**：把"收集到错题本"固化成标准 Agent skill / automation，入库前自动展示待入库清单让人确认。
5. **复盘未自动化**：建一个每周 Agent automation，定时拉 `/api/v1/stats` 生成周报（易错点 TOP5、本周新增/掌握数、推荐下周重做范围）。
6. **复习无间隔策略**：目前只有"待重做/已掌握"两态。→ 远期引入简化版间隔重复（如 1 天/3 天/7 天/14 天梯次），云端按 `next_review_at` 推荐组卷范围。

## 五、分阶段实施路线

- **阶段 1 · 跑通闭环**（现有代码即可）：部署阿里云 → 配置 AI Agent 服务地址 + API Key → 走通"拍卷子→入库→打印→扫码→重做→统计"全流程。目标：真实用起来一周。
- **阶段 2 · 数据质量**：知识点字典表 + 别名归一；图片上传；扫码 token 防刷。目标：统计数字可信、安全兜底。
- **阶段 3 · 自动化复盘**：AI Agent skill（收集/查询/出卷指令标准化）+ 每周自动周报 automation。目标：不动手就能拿到复盘结论。
- **阶段 4 · 智能复习**：间隔重复调度、按 `next_review_at` 自动推荐每日重做题组、手机拍照复批。目标：从"错题本"升级为"复习调度系统"。

## 六、关键设计决策（为什么这么分）

1. **数据只存云端一份**：电脑、手机、AI 都是客户端，避免多端同步问题。
2. **AI 无状态**：AI 负责所有"需要智力"的环节（批改/打标/出报告），但不持有数据；系统离了 AI 仍能手动运转，AI 换了对话也能靠 API 恢复上下文。
3. **掌握判定在云端规则化**：不靠 AI 记忆，规则简单可解释（连续 2 次对），孩子和家长都能理解。
4. **纸笔为核心交互**：重做必须在纸上做（符合真实考试场景），手机只做"对答案 + 反馈"，避免变成刷手机。
5. **二维码是纸与云的桥梁**：一张纸链接云端单题，答案不上纸是防作弊核心设计。
