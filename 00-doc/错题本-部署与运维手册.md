## 二、架构要点

```
手机 AI Agent ─拍照→ AI 批改/提取/打标 →(X-API-Key)→ nginx(5173)/cuoti/ → Go(8090) → MySQL
                                                  │
            管理页 /cuoti/ · 打印页 /cuoti/print · 扫码页 /cuoti/m/:id
```

- 代码用 `BASE_PATH` 环境变量适配子路径（本地开发不设即根路径）
- 掌握判定在云端：连续 2 次重做做对 → "已掌握"；做错 → 回"待重做"
- 打印页每题带二维码（`PUBLIC_BASE_URL=http://${SERVER_IP}:5173/cuoti`），答案不上纸
- 服务器上若有其他同机服务，配置 Nginx 时需独立二级路径，互不干扰

## 三、本机一键部署流程（标准操作）

项目现已实现一键自动化部署脚本（自动从 `.env` 读取配置，交叉编译 Linux amd64 后端 + 构建 Vue 3 前端 + 同步至云服务器 + 重启 systemd 并进行内外网冒烟探活）：

```bash
cd /path/to/mistake-book-helper

# 1. 确保本地 .env 配置了 DEPLOY_SERVER_HOST 等信息
# 2. 一键部署至云服务器
make deploy
# 或直接执行：./script/deploy-aliyun.sh
```

脚本将自动执行：
1. 本机交叉编译 `mistakebook-linux-amd64`
2. 前端构建 `VITE_BASE_PATH=/cuoti/ npm run build`
3. 通过 scp 与 tar 流式同步二进制与 `dist` 到 `${DEPLOY_SERVER_USER}@${DEPLOY_SERVER_HOST}:/opt/mistakebook/`
4. 远端 `systemctl restart mistakebook` 重启服务
5. 自动验证内网 8090 及公网 5173 `/cuoti/healthz` 探活响应（HTTP 200）

## 五、升级同步规程（重要，固定执行）

**只要升级涉及以下任一项，必须在当次升级内同步更新两处：**

| 变更内容 | 需同步 |
|---|---|
| API 契约（路径/参数/JSON 字段） | ① 本机 skill `~/.workbuddy/skills/mistakebook/SKILL.md` ② 资料库《错题本-WorkBuddy指令卡》 ③ 本手册 |
| 服务地址 / API Key / 端口 | 同上 ①②③ |
| UI 操作方式（页面功能变化） | 资料库指令卡（若影响使用说明）+ 本手册 |
| 纯 bug 修复 / 内部重构 | 本手册"已验证"小节即可 |

资料库更新方式：指示 AI Agent "把工作区里的《错题本-WorkBuddy指令卡.md》更新到资料库"，或用 LibraryUpload 重新上传同名文件（覆盖旧版，node_id 不变即成功）。

**为什么**：手机端云端模式读不到本机 skill，全靠资料库指令卡；不同步会导致手机端用过期的地址/Key/契约。

## 六、移动端使用路径（双保险）

1. **电脑开机时**：手机 AI Agent "连接电脑"模式（或通过客户端绑定桌面端）→ 桌面端自动加载本机 skill，拍照批改后说"上传错题"即可。
2. **电脑关机时**：手机 AI Agent 云端模式 → 说"错题本指令卡在资料库里，按它把错题上传到错题本"→ 它检索指令卡后调 API。
